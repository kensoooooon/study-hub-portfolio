# AI Workflow — このディレクトリについて

このディレクトリは、実プロジェクト(このリポジトリのサニタイズ元となった開発中のDjangoアプリケーション)で実際に運用している「AIとの協業を構造化・監査可能にするためのドキュメント体系」の抜粋・一般化版です。

README(トップ)の「Development Process」では開発フローを文章で説明していますが、ここではその実体——AIが何を読み、いつ立ち止まり、何を記録するかを規定するルールブックそのもの——を置いています。

## なぜこれを作ったか

AIに実装を任せる機会が増えるほど、「AIが正しい前提で動いているか」「過去に外した予測を次回も繰り返していないか」「取り返しのつかない操作の前に人間の判断を挟めているか」が開発速度のボトルネックになります。このディレクトリの各ドキュメントは、その課題に対する具体的な運用ルールです。

## 含まれるもの

| ファイル | 役割 |
|---|---|
| [`CLAUDE.md`](CLAUDE.md) | AIアシスタント向けの作業ルールブック本体。テナント境界の扱い方、作業の納品フロー(人間がcommit/pushする)、テストへのドキュメント付与義務などを定義 |
| [`README_AI.md`](README_AI.md) | AIが「どのドキュメントを、いつ、どの順番で読むべきか」を規定するメタドキュメント。Risk-First Planning Rule(状態変更・リスク・人間判断事項を先に開示する形式)を含む |
| [`ai_memory/README.md`](ai_memory/README.md) | 「Prediction Correction(予測ズレ記録)」という1つの形式に統一したAIメモリ運用方針。記録は人間がトリガーを握り、AIが自動生成しない設計 |
| [`ai_memory/INDEX.md`](ai_memory/INDEX.md) | AI Memoryの入口となる1行要約インデックス(テンプレート例のみを収録した縮小版) |
| [`work_items/example-migration/README.md`](work_items/example-migration/README.md) | 破壊的なDBスキーマ変更を、Characterize→Expand→Switch→Contractの4フェーズに分けて安全に進めるためのワークアイテム運用例(架空のIssue番号による再構成版) |

## 注意

実プロジェクトのAI Memoryには、実際のバグ調査で見つかった具体的なコード上の指摘事項が記録されていますが、その中には修正時期を意図的に調整している内容も含まれるため、ここには転載していません。`ai_memory/README.md`内のテンプレート例(実際の事例ではない、と明記されています)が、運用形式の実演として十分に機能します。
